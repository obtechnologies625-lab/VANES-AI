# VANES AI database setup (Cloudflare Dashboard only)

The repository contains a privacy-aware analytics API and a private admin dashboard. Both need a D1 database bound to the Worker. Without the binding every `/api/analytics` request returns `503 Analytics database is not configured yet.` and events are discarded — the app itself keeps working normally.

You do not need Command Prompt, Node.js or wrangler for any of this.

## 1. Create the database

In the Cloudflare Dashboard:

1. Open **Workers & Pages**.
2. Open the **D1 SQL database** tab (left sidebar, or the *Storage & databases* section).
3. Click **Create database**.
4. Name it `vanes-ai-db`.
5. Choose the default location and confirm.

## 2. Get the database ID

1. Open the `vanes-ai-db` database you just created.
2. Click the **Settings** tab.
3. Copy the **Database ID** — a UUID such as `1a2b3c4d-0000-1111-2222-333344445555`.

You will paste this into the repository in step 3, not into the dashboard.

## 3. Bind it in `wrangler.toml`

Add this block to `wrangler.toml`, replacing the UUID with yours:

```toml
[[d1_databases]]
binding = "DB"
database_name = "vanes-ai-db"
database_id = "PASTE-YOUR-DATABASE-ID-HERE"
```

Then commit and push to `main`. The Cloudflare deploy workflow runs `wrangler deploy`, which applies the binding.

> **Do not add the binding through the dashboard instead.** `wrangler deploy` reconciles bindings against `wrangler.toml`, so a binding created by hand in the dashboard is **removed by the next deploy**. `wrangler.toml` is the only durable place for it.
>
> Equally, do not add the `[[d1_databases]]` block before the database exists — `wrangler deploy` fails on an unknown `database_id`, and a failed deploy leaves production on the previous version.

The API creates the `vanes_users` and `vanes_events` tables automatically on the first request, so no migration step is required. Applying `schema.sql` is optional; it creates the same tables plus indexes that make the admin dashboard queries faster as the data grows:

1. Open `vanes-ai-db` → **Console** tab.
2. Paste the contents of `schema.sql`.
3. Click **Execute**.

## 4. Protect and open the developer dashboard

In the Cloudflare Dashboard, open **Workers & Pages → vanes-ai → Settings → Variables and Secrets**, and add a secret:

- Type: **Secret**
- Name: `ADMIN_ANALYTICS_TOKEN`
- Value: a long random private token known only to you

Then open the dashboard by putting that same token in the URL:

```
https://vanes-ai.obtechnologies625.workers.dev/admin-analytics.html?key=YOUR_TOKEN
```

The page is generated by the Worker and is **not** a file in the deployed site. A wrong or missing `key` returns a plain `404 Not found`, so the dashboard is not discoverable without the token. Bookmark the URL with your token in it; the page prefills the token and loads the data immediately.

The dashboard shows registered learner identities, total event counts and the 100 most recent events. The same token is the only way to read `/api/admin/analytics`.

## 5. Verify it worked

```
https://vanes-ai.obtechnologies625.workers.dev/api/health
```

Look for `"analyticsEnabled":true` and `"adminAnalyticsConfigured":true`. If `analyticsEnabled` is `false` the `DB` binding did not reach the Worker — re-check `wrangler.toml` and the latest deploy.

## 6. Automatic deployment

The Cloudflare deployment workflow is at `.github/workflows/deploy-cloudflare.yml`. It needs these GitHub repository secrets under **Settings → Secrets and variables → Actions**:

- `CLOUDFLARE_API_TOKEN`
- `CLOUDFLARE_ACCOUNT_ID`

If they are missing the workflow prints *"Cloudflare secrets are not configured; deployment is skipped"* and **still reports success**, so always confirm the `Deploy Worker` step conclusion rather than the run badge.

## Privacy

VANES uses an anonymous browser identifier. Question and answer content is not sent for improvement unless the learner explicitly enables the anonymised-learning-data option in Settings. Names, phone numbers and payment credentials are not part of the analytics event payload.
